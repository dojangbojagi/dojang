Prove it without showing it.

Pick an eligibility policy. Your device builds a proof that your sealed credential meets it. Only the proof and the public inputs leave your device.

Placeholder page. The full design for this page is the next step. The header, footer, scenarios and the plan below already follow the master brief.

What this page will do

  • Explain the sample policy (at least 1,000 verified test units), the credential in use, what stays private and what is public.
  • Check the wallet, the credential’s expiry and revocation, and the network before a proof can be made.
  • Generate the proof, offer an optional local check, then pass it to the vault action for on-chain verification.
  • Show “Proof Generated” separately from “Proof Verified On-chain” and “Vault Action Confirmed”.
  • Keep the exact value out of logs, analytics, the address bar, transaction arguments and events.
  • If a browser cannot prove, a server prover may exist only as a flagged demo fallback, with a plain warning that sending the value to a server changes the privacy.

Eligibility privacy only. The exact value stays private, but your wallet address and the transaction stay visible. This is not GIWA’s native Bojagi private transfer.
